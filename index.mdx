You only need an enabled Launchpoint account, an API key, and a server that can keep that key private.

<Steps>
  <Step title="Create an API key">
    Open [Dashboard → Settings → API](https://dashboard.launchpointhq.com/settings#api), then create a key.

    API access must be enabled for your company. If the API section is hidden, ask [Launchpoint support](mailto:hi@launchpointhq.com) to enable it.

    <Warning>
      Copy the key when it is created. Keep it out of browser code, mobile apps, logs, and source control.
    </Warning>
  </Step>

  <Step title="Store the key on your server">
    Add the key to your server environment:

    ```bash
    export LAUNCHPOINT_API_KEY="lp_pk_..."
    ```
  </Step>

  <Step title="Fetch your programs">
    Send the key in the `x-api-key` header:

    <CodeGroup>
      ```bash cURL
      curl "https://dashboard.launchpointhq.com/api/v1/programs" \
        --header "x-api-key: $LAUNCHPOINT_API_KEY"
      ```

      ```javascript JavaScript
      const response = await fetch(
        "https://dashboard.launchpointhq.com/api/v1/programs",
        {
          headers: {
            "x-api-key": process.env.LAUNCHPOINT_API_KEY,
          },
        },
      );

      if (!response.ok) {
        throw new Error(`Launchpoint API returned ${response.status}`);
      }

      const programs = await response.json();
      ```
    </CodeGroup>
  </Step>
</Steps>

## Check the response

A successful list request returns `data`, `page`, and `total`:

```json
{
  "data": [],
  "page": 1,
  "total": 0
}
```

Every response also includes `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` headers.

## Use company or agency scope

Routes that support `scope` use `scope=company` by default. This returns only the API key company's data.

A parent agency can pass `scope=agency` to include its own data and data from linked brands. Other keys receive `403` for this scope.

## Creator privacy

API responses never include creator phone numbers or email addresses.

## Stay within the rate limit

The standard limit is 100 requests per minute per API key. Approved partner accounts receive 400 requests per minute. Requests over the limit return `429`.

## Handle errors by status

Errors use this shape:

```json
{ "error": "Invalid request" }
```

Some errors also include a `code`.

| Status | Meaning |
| --- | --- |
| `400` | The request is missing or has an invalid value. |
| `401` | The API key is missing or invalid. |
| `402` | API access or the company's payment setup is not ready. |
| `403` | The key cannot access the requested company or agency scope. |
| `404` | The requested record was not found. |
| `429` | The API key has reached its per-minute limit. |
| `500` | Launchpoint could not complete the request. |

## Read timestamps and pages

Timestamps are Unix timestamps in milliseconds unless a field says otherwise.

Most list endpoints accept `page` and `limit` and return `data`, `page`, and `total`. Some also return `totalPages`.
