<Note>
  **The Launchpoint Public API is in private preview.** Availability is limited to trusted partners we work with directly. There is no self-serve signup; access is reviewed case by case. To ask about access, email [Launchpoint support](mailto:hi@launchpointhq.com).
</Note>

All you need is an enabled Launchpoint account, an API key, and a server that can hold that key privately.

<Steps>
  <Step title="Create an API key">
    Go to [Dashboard → Settings → Developer](https://dashboard.launchpointhq.com/campaigns?settings=api) and generate a key.

    Your company needs API access turned on first. While the API stays in private preview, the Developer section is hidden for most companies and enabled only for trusted partners. If it is not there, email [Launchpoint support](mailto:hi@launchpointhq.com) to ask about access.

    <Warning>
      Copy the key at creation time. Never place it in browser code, mobile apps, logs, or source control.
    </Warning>
  </Step>

  <Step title="Store the key on your server">
    Set the key in your server environment:

    ```bash
    export LAUNCHPOINT_API_KEY="lp_pk_..."
    ```
  </Step>

  <Step title="Fetch your programs">
    Pass the key through the `x-api-key` header:

    <CodeGroup>
      ```bash cURL
      curl "https://dashboard.launchpointhq.com/api/v1/programs" \
        --header "x-api-key: $LAUNCHPOINT_API_KEY"
      ```

      ```javascript JavaScript
      const response = await fetch(
        "https://dashboard.launchpointhq.com/api/v1/programs",
        {
          headers: {
            "x-api-key": process.env.LAUNCHPOINT_API_KEY,
          },
        },
      );

      if (!response.ok) {
        throw new Error(`Launchpoint API returned ${response.status}`);
      }

      const programs = await response.json();
      ```
    </CodeGroup>
  </Step>
</Steps>

## Read the response

A list request that succeeds comes back with `data`, `page`, and `total`:

```json
{
  "data": [],
  "page": 1,
  "total": 0
}
```

The `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` headers are attached to every response.

## Use company or agency scope

Any route that supports `scope` defaults to `scope=company`, which returns data belonging to the API key's company only.

A parent agency may send `scope=agency` to cover its own data plus the data of linked brands. Every other key gets a `403` for that scope.

## Creator privacy

Creator email addresses are never present in API responses.

`GET /creators` can return a creator `phone`. That field is `null` when there is no number on file or your workspace does not have access to creator contact details.

## Stay within the rate limit

Each API key gets 100 requests per minute by default, and approved partner accounts get 400 per minute. Anything beyond the limit returns `429`.

## Handle each error status

Errors come back in this shape:

```json
{ "error": "Invalid request" }
```

A `code` is included on some errors.

| Status | Meaning |
| --- | --- |
| `400` | A required value is missing, or a supplied value is invalid. |
| `401` | No API key was sent, or the key is invalid. |
| `403` | The key is not allowed to reach the requested company or agency scope. |
| `404` | No matching record exists. |
| `429` | The API key hit its per-minute limit. |
| `500` | Launchpoint was unable to complete the request. |

## Work with timestamps and paging

Unless a field states otherwise, timestamps are Unix timestamps in milliseconds.

Most list endpoints take `page` and `limit`, then return `data`, `page`, and `total`. A few add `totalPages`.
